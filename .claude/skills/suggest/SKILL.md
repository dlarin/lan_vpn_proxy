# Чеклист предложений

Цель — актуальный список конкретных доработок в `.claude/suggestions.md`, из которого пользователь выбирает, что делать. Сам ничего не исправляй — только записывай.

Область или акцент (может быть пусто — тогда весь проект): $ARGUMENTS

## Шаги

1. **Прочитай контекст.** `.claude/context.md` (решения, отвергнутые варианты, предпочтения, открытые задачи), текущий `.claude/suggestions.md`, если есть, `git log --oneline -15`, `git status --short`.

2. **Изучи код** в нужной области: скрипты, службы systemd, compose, `web.py`, `static/index.html`, тесты, README. Ищи:
   - **Исправить** — ошибки, гонки, необработанные случаи, расхождения README и кода;
   - **Безопасность** — секреты, права файлов, доступ извне, проверка ввода;
   - **Надёжность** — что сломается при падении сервера, без интернета, после перезагрузки, при смене версии;
   - **Улучшить** — удобство интерфейса, упрощение кода, дублирование;
   - **Тесты и документация** — что не покрыто, что устарело;
   - **Сделать** — новые возможности, полезные для цели проекта.

3. **Отсей лишнее.** Не предлагай то, что в контексте записано как отвергнутое или противоречит предпочтениям пользователя (например, ставить новое ПО на ноутбук), — разве что появилась новая причина, тогда укажи её. Не дублируй «Открытые задачи» из контекста. Каждый пункт проверь по коду: файл, строка, команда должны существовать.

4. **Объедини со старым списком.** Сделанные пункты отметь `[x]` (проверь по коду и git) и перенеси в «Сделано», неактуальные удали, новые добавь. Отклонённые пользователем — в «Отклонено» с причиной, чтобы не предлагать снова.

5. **Запиши `.claude/suggestions.md`** по шаблону.

6. **Ответь пользователю** коротко: сколько пунктов, 3–5 самых важных с номерами, путь к файлу. Предложи выбрать, что делать. Не коммить.

## Правила

- Пункт — одна строка: что сделать, где (`файл:строка`) и зачем, плюс оценка: важность (🔴 высокая, 🟡 средняя, ⚪ низкая) и объём (S/M/L).
- Внутри разделов — по убыванию важности. Номера сквозные и не меняются между запусками, чтобы на них можно было ссылаться («сделай 7»); новым — следующий свободный номер.
- Конкретно: не «улучшить обработку ошибок», а «`proxy-watch.sh:42` — при падении `gsettings` цикл завершается, добавить `|| true`».
- Никаких секретов из `.env`, `data/` и подписки.
- Даты абсолютные. Пиши на русском.

## Шаблон

```markdown
# Предложения по проекту

_Обновлено: ГГГГ-ММ-ДД. Файл ведёт скил `/suggest`._

## Исправить
- [ ] **1.** 🔴 S — <что и где> — <почему>

## Безопасность
## Надёжность
## Улучшить
## Тесты и документация
## Сделать

## Сделано
- [x] **N.** <что> — ГГГГ-ММ-ДД

## Отклонено
- **N.** <что> — <причина>
```

Пустые разделы удаляй.

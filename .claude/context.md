## Решения
- В Docker — Xray, а не сам Happ: Happ — GUI-обёртка, внутри у него тот же Xray.
- Образ `ghcr.io/xtls/xray-core:26.7.28` закреплён — та же версия, что в Happ. Образ distroless (без shell), поэтому без healthcheck. Работает от `PUID` 1000, чтобы читать `config.json` с правами 600.
- Порты 1080 (SOCKS5) и 3128 (HTTP), а не 10808/10809, как у Happ, — чтобы до переключения обе схемы работали одновременно.
- Системный прокси GNOME вместо TUN: через VPN идут только программы, которые используют прокси. TUN в контейнере требует `--network host` и NET_ADMIN — по сути тот же Happ.
- Переключение — по `docker events` (пользовательская служба systemd). Если служба остановлена — прокси выключается (`ExecStopPost`): лучше напрямую, чем в мёртвый прокси. PAC с `PROXY …; DIRECT` не взяли: браузеры запоминают упавший прокси на минуты (Firefox — до 30 мин).
- `proxy-watch.sh` не подключает `.env` через `source`: bash выполнил бы `&` и `$(…)` из ссылок подписки.
- `BIND_ADDR=127.0.0.1` по умолчанию: прокси без пароля, а пользователь часто сидит в отельных Wi-Fi.
- Отвергнуто: sing-box, proxychains (пользователь не хочет ничего ставить); policy routing через `ip rule`/`nft` (Happ сам управляет маршрутами, сложнее).

## Грабли
- Подписка Happ в `~/.config/Happ/subs.db` зашифрована — достать нельзя, нужна обычная ссылка от провайдера. Ссылки `happ://…` не поддерживаются.
- Тестовый REALITY-сервер с target `www.microsoft.com` не завершал рукопожатие; с `www.google.com` и `www.apple.com` работает. Клиент тут ни при чём.
- В образе Xray нет `/bin/sh`: проверять конфиг через `docker run … run -test -c /путь/config.json`. `xray x25519` называет публичный ключ «Password (PublicKey)».
- Тестировать наблюдатель, не трогая настоящие настройки GNOME: `GSETTINGS_BACKEND=keyfile XDG_CONFIG_HOME=/tmp/…`. `setsid` в тестах отделяет процесс — фоновые копии надо добивать по session id.
- Отсутствующую папку для bind mount Docker создаёт от root — поэтому в git есть `xray/.gitkeep`.
- Docker-сеть `br-6d2c0d7f0fb1` (172.19.0.0/16) пересекается с интерфейсом `happ-xray` (172.19.0.1/30) — исчезнет вместе с Happ.
- Контейнеры `jarvis-*` (включая `jarvis-torrent`) сейчас идут через VPN из-за TUN Happ. После переключения пойдут напрямую, если не прописать им прокси.

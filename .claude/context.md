# Контекст проекта

_Обновлено: 2026-10-19. Файл ведёт скил `/save-context`._

## Цель
Заменить VPN-клиент Happ на ноутбуке (Ubuntu, GNOME) на Xray в Docker. Правило пользователя: **контейнер запущен — трафик через VPN, остановлен — напрямую.** Плюс управление рабочим VPN Cisco Secure Client из того же веб-интерфейса. Второй вариант установки — домашний сервер (Debian) как шлюз с VPN для всех устройств сети. Подробности и команды — в `README.md`.

## Решения
- В Docker — Xray, а не сам Happ: Happ — GUI-обёртка, внутри у него тот же Xray.
- Образ `ghcr.io/xtls/xray-core:26.7.28` закреплён — та же версия, что в Happ. Distroless (без shell), поэтому без healthcheck. Работает от `PUID` 1000, чтобы читать `config.json` с правами 600.
- Порты 1080 (SOCKS5) и 3128 (HTTP), а не 10808/10809, как у Happ, — чтобы при переходе обе схемы работали одновременно.
- Контейнер в `network_mode: host`: в сети bridge Xray видел вместо порта программы `docker-proxy`. Адрес и порты из `.env` `gen_config.py` пишет прямо в конфиг Xray.
- `pid: host` + `apparmor=unconfined` — иначе правила по приложениям не работают.
- Системный прокси GNOME вместо TUN: через VPN идут только программы, которые используют прокси.
- Переключение — по `docker events`: фильтр по точному имени, пауза `RESTART_GRACE` (5 с) перед выключением прокси, при остановке службы прокси выключается (`ExecStopPost`).
- `proxy-watch.sh` не подключает `.env` через `source`: bash выполнил бы `&` и `$(…)` из ссылок подписки. `.env` перечитывается при каждой синхронизации — так новый `DIRECT_HOSTS` попадает в исключения GNOME после перезапуска контейнера.
- `BIND_ADDR=127.0.0.1` по умолчанию: прокси без пароля, а пользователь часто сидит в отельных Wi-Fi.
- Веб-интерфейс — только стандартная библиотека Python, слушает `127.0.0.1`, проверяет Host и Origin, действия принимает только как JSON.
- `DIRECT_HOSTS` («Всегда напрямую») — правило Xray раньше правил VPN плюс исключения прокси GNOME. Нужно, чтобы рабочие сайты в любом режиме шли мимо Xray и попадали в туннель Cisco.
- Cisco — через его консольную утилиту `/opt/cisco/secureclient/bin/vpn` в псевдотерминале (`setsid -wc`), ответы по тексту вопроса сервера. Пароль и код не сохраняются.
- Cisco в Docker через openconnect — отвергнуто: сервер проверяет состояние ноутбука (posture/HostScan), openconnect пришлось бы её подделывать — обход защиты работодателя.
- Пока открыто окно Cisco (`vpnui`), веб-интерфейс только подсказывает его закрыть, сам не закрывает — выбор пользователя.
- Состояние Cisco — по наличию интерфейса `cscotun0`, а не через `vpn state` (2 с и спам в журнале).
- Оформление Ant Design — на чистом CSS. Библиотеку antd не подключали: React, CDN в странице с паролем Cisco и управлением Docker, не работала бы без интернета.
- HTTPS — самоподписанный сертификат через системный `openssl`, а не через `xray tls cert`: у Xray IP попадает в SAN как DNS-имя, а ключ подписан `RSA PRIVATE KEY` (на деле EC), и Python его не загружает.
- Неудачной попыткой входа считается только запрос с неверным заголовком `Authorization`: первый запрос браузера идёт без пароля.
- PAC с `PROXY …; DIRECT` не взяли: браузеры запоминают упавший прокси на минуты.
- Git на `green` (`git push green` + хук) — сделали и убрали: пользователь предпочёл обновлять вручную через `scp`.
- Проверка текущего сервера — через отдельный вход `health` (правило первым, `inboundTag → proxy`): обычный HTTP-вход в режиме filter отправил бы проверочный запрос напрямую. Вход исключён из учёта трафика.
- Автопереключение не возвращается на прежний сервер, когда тот оживёт: лишние переключения рвут соединения. Если не работает ни один сервер — ничего не меняем (скорее нет интернета).
- `SUBSCRIPTION_REFRESH` обновляет только список и ключи (`gen_config.py -o` во временный файл), рабочий конфиг не трогает — иначе ротация адресов провайдера перезапускала бы VPN каждый раз.
- Шлюз — `gateway/compose.yml` поверх основного (через `COMPOSE_FILE` в `.env`, ставит `install-gateway.sh`): без `pid: host`, AppArmor по умолчанию, `cap_drop: ALL` + `NET_ADMIN` (TPROXY) + `DAC_READ_SEARCH` (root читает `config.json` с правами 600 пользователя), `read_only`, `no-new-privileges`. Root остаётся: Docker не даёт ambient-capabilities не-root процессу.
- Отвергнуто: sing-box, proxychains (ничего не ставить); policy routing через `ip rule`/`nft`.

## Грабли
- Подписка Happ в `~/.config/Happ/subs.db` зашифрована, ссылки `happ://…` не поддерживаются — нужна обычная ссылка провайдера.
- С XTLS Vision данные идут мимо счётчиков outbound `proxy` — трафик считаем по inbound минус `direct`.
- `docker events --filter container=…` совпадает по части имени (ловил `lan-vpn-proxy-check`).
- Если быстро переключать прокси, программы держат прямые соединения часами — отсюда `RESTART_GRACE`.
- Профиль AppArmor `docker-default` не даёт Xray читать `/proc/<pid>/fd` процессов хоста.
- Утилита Cisco `vpn` не подключается, пока открыт `vpnui`: «Connect capability is unavailable». После отключения окно Cisco может снова оказаться открытым.
- `vpn state` — около 2 с и ~7 строк в журнал службы на каждый вызов.
- Cisco при подключении заменяет `/etc/resolv.conf` своими DNS (копия — `resolv.conf.vpnbackup`), а у контейнера Xray остаётся копия на момент создания (`127.0.0.53`). Внутренние имена через Xray не резолвятся — рабочие домены держать в `DIRECT_HOSTS`.
- Запись `*` в исключениях GNOME пускает мимо прокси всё — `proxy-watch.sh` такие записи отбрасывает.
- В `~/.ssh/known_hosts` был отозванный в 2023 году RSA-ключ GitHub — заменён ключами из `gh api meta` (копия — `known_hosts.old`).
- Тестовый REALITY-сервер с target `www.microsoft.com` не завершал рукопожатие; с `www.google.com` работает.
- В образе Xray нет `/bin/sh`: конфиг проверять через `docker run … run -test -c …`; файлы из контейнера — `docker cp lan-vpn-proxy:/путь -`.
- Тестировать наблюдатель, не трогая GNOME: `GSETTINGS_BACKEND=keyfile XDG_CONFIG_HOME=/tmp/…`; функции — `source <(sed '/^while true/,$d' proxy-watch.sh)`.
- Тестировать вход Cisco — поддельной утилитой `vpn` (bash-скрипт с вопросами), подменив `web.CISCO_VPN`.
- Смотреть страницу — `google-chrome --headless=new --screenshot`; тёмная/светлая тема — `--blink-settings=preferredColorScheme=0/1` (система по умолчанию тёмная).
- Отсутствующую папку для bind mount Docker создаёт от root — поэтому в git есть `xray/.gitkeep`.
- TLS-рукопожатие — в потоке запроса (`do_handshake_on_connect=False`), иначе медленный клиент блокирует `accept`; ошибки `ssl.SSLError` (открыли `http://`) глушатся в `Handler.handle`.
- `gen_config.py` при каждом запуске заново качает подписку, а провайдер раздаёт адреса по очереди (`rucash`/`rucash2`) — конфиг каждый раз другой. Поэтому `install-gateway.sh` собирает конфиг только если его нет.
- IPv6 в домашней сети нет (2026-10-19: у `green` и ноутбука только `fe80::`), поэтому правила шлюза только для IPv4. Если роутер или провайдер включат IPv6 — устройства пойдут по нему мимо VPN, нужны правила для `ip6`.
- В compose `!reset` для списка сбрасывает и новое значение — для замены списка нужен `!override` (Compose ≥ 2.24; на `green` 2.26).
- Ключ REALITY в тестах должен быть в формате x25519 (32 байта base64url) — иначе `xray run -test` отвергает конфиг.
- Тестировать `web.py` на свободном порту: `WEB_BIND=127.0.0.2 WEB_PORT=… WEB_HOSTS=127.0.0.2 WEB_PASSWORD=… timeout 6 python3 web.py` (переменные окружения важнее `.env`); созданный `data/web.*` потом удалить.
- Контейнеры `jarvis-*` теперь ходят напрямую; если им нужен VPN, надо прописать прокси.

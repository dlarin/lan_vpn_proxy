## Решения
- В Docker — Xray, а не сам Happ: Happ — GUI-обёртка, внутри у него тот же Xray.
- Образ `ghcr.io/xtls/xray-core:26.7.28` закреплён — та же версия, что в Happ. Образ distroless (без shell), поэтому без healthcheck. Работает от `PUID` 1000, чтобы читать `config.json` с правами 600.
- Порты 1080 (SOCKS5) и 3128 (HTTP), а не 10808/10809, как у Happ, — чтобы при переходе обе схемы работали одновременно.
- Контейнер в `network_mode: host`: в сети bridge Xray видел вместо порта программы `docker-proxy`. Адрес и порты из `.env` `gen_config.py` пишет прямо в конфиг Xray.
- `pid: host` + `apparmor=unconfined` — иначе правила по приложениям не работают. Если они не нужны, оба параметра можно убрать (см. раздел README «Безопасность»).
- Системный прокси GNOME вместо TUN: через VPN идут только программы, которые используют прокси. TUN в контейнере требует NET_ADMIN — по сути тот же Happ.
- Переключение — по `docker events` (пользовательская служба systemd):
  - события фильтруются по точному имени контейнера;
  - прокси выключается через `RESTART_GRACE` (5 с) после остановки, чтобы перезапуск или смена сервера не уводили программы на прямые соединения;
  - если служба остановлена, прокси выключается (`ExecStopPost`).
- PAC с `PROXY …; DIRECT` не взяли: браузеры запоминают упавший прокси на минуты (Firefox — до 30 мин).
- `proxy-watch.sh` не подключает `.env` через `source`: bash выполнил бы `&` и `$(…)` из ссылок подписки.
- `BIND_ADDR=127.0.0.1` по умолчанию: прокси без пароля, а пользователь часто сидит в отельных Wi-Fi.
- Веб-интерфейс:
  - написан на стандартной библиотеке Python;
  - слушает только `127.0.0.1`, проверяет Host и Origin, действия принимает только как JSON.
- Проверка серверов — полный HTTP-запрос через временный контейнер `lan-vpn-proxy-check`: ответ на TCP-подключение не доказывает, что VPN работает.
- «Обновить подписку» перезапускает контейнер, только если изменилось что-то кроме `shortId`: провайдер отдаёт разный `shortId` REALITY при каждом запросе.
- Трафик «через VPN» = inbound минус outbound `direct`; «напрямую» = сетевые карты минус VPN.
- Вкладка «Хосты» считает долю по числу подключений, а не по байтам: Xray не считает байты по хостам.
- Отвергнуто: sing-box, proxychains (пользователь не хочет ничего ставить); policy routing через `ip rule`/`nft` (сложнее, а Happ сам управлял маршрутами).

## Грабли
- Подписка Happ в `~/.config/Happ/subs.db` зашифрована — достать нельзя, нужна обычная ссылка от провайдера. Ссылки `happ://…` не поддерживаются.
- С XTLS Vision данные после рукопожатия идут мимо счётчиков outbound `proxy` — считать по ним нельзя.
- Фильтр `docker events --filter container=lan-vpn-proxy` срабатывал и на `lan-vpn-proxy-check`: после проверки серверов прокси выключался.
- Если быстро переключать прокси, программы открывают прямые соединения и держат их часами — отсюда `RESTART_GRACE`.
- Профиль AppArmor `docker-default` не даёт Xray читать `/proc/<pid>/fd` процессов хоста.
- Приложение на вкладке «Хосты» определяется через `ss` раз в 2 с. Короткие подключения и процессы других пользователей (без root) попадают в «не определено».
- Тестовый REALITY-сервер с target `www.microsoft.com` не завершал рукопожатие; с `www.google.com` и `www.apple.com` работает. Клиент тут ни при чём.
- В образе Xray нет `/bin/sh`: проверять конфиг через `docker run … run -test -c /путь/config.json`. `xray x25519` называет публичный ключ «Password (PublicKey)».
- Тестировать наблюдатель, не трогая настоящие настройки GNOME: `GSETTINGS_BACKEND=keyfile XDG_CONFIG_HOME=/tmp/…`. `setsid` в тестах отделяет процесс — фоновые копии надо добивать по session id.
- Отсутствующую папку для bind mount Docker создаёт от root — поэтому в git есть `xray/.gitkeep`.
- Контейнеры `jarvis-*` (включая `jarvis-torrent`) раньше шли через VPN из-за TUN Happ, теперь — напрямую. Если нужен VPN, им надо прописать прокси.
